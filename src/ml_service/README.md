# Comments on the ML-related side 

This microservice loads the trained ```.pkl``` model generated by your initContainer from ```/mnt/data/fraud_model.pkl```.   

## ML Model path and helm chart:

MODEL_PATH is being defined by Kubernetes through the Helm deployment

```MODEL_PATH=/mnt/data/fraud_model.pkl```   

But Kubernetes is mounting a volume into the container at:

```/mnt/data```   

So the overall set up is:   

```
Kubernetes Pod      
│     
├── Container: ml-api      
│   │     
│   ├── Environment variable:   
│   │     MODEL_PATH=/mnt/data/fraud_model.pkl   
│   │   
│   └── /mnt/data  ◄──── mounted volume   
│          │   
│          └── fraud_model.pkl   
│    
└── Volume: ml-data-volume   
```

Therefore the app looks for the model in ```/mnt/data/fraud_model.pkl``` inside the container, but that ```/mnt/data directory``` is actually backed by the external Kubernetes volume at node level.

## Dockerfile Python details
### Python Environment Variables (Used in BOTH)   
in both docker files:
```
ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1
```

- ```PYTHONDONTWRITEBYTECODE=1```: Stops Python from compiling ```.pyc``` files inside the container. Since container filesystems are immutable during execution, ```.pyc``` files just waste disk space and slow down image builds.   

- ```PYTHONUNBUFFERED=1```: Forces Python to flush its ```stdout``` and ```stderr``` streams immediately. Without this, logs get buffered in memory, meaning when you run ```kubectl logs <pod-name>```, your application logs will be delayed or missing entirely during a crash.   

### System Dependencies (Used in BOTH)   
```
RUN apt-get update && apt-get install -y --no-install-recommends \
    curl \
    && rm -rf /var/lib/apt-get/lists/*
```   

- ```--no-install-recommends```: Avoids installing bloatware package dependencies, keeping your Docker image lean.
- ```rm -rf /var/lib/apt-get/lists/*```: Cleans up the APT package indexes right after installation, saving 30–50MB of unnecessary layer size.
- ```curl```: Provides the CLI utility required for container-level healthchecks.

### Docker Healthchecks (Service Specific)

- For src/frontend/Dockerfile (Streamlit), Streamlit exposes a built-in health endpoint at ``_stcore/health``:    
```HEALTHCHECK CMD curl --fail http://localhost:8501/_stcore/health || exit 1```   


- For ```src/ml_service/Dockerfile```, FastAPI / Uvicorn exposes documentation at ```/docs``` by default (or any root endpoint):   
```HEALTHCHECK CMD curl --fail http://localhost:8000/docs || exit 1 ```
